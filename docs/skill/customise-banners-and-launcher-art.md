# Skill 13 — Customise the launcher banner, welcome background, and TV banner art

## Goal

Rebrand every "big art" surface of the app — the Android TV launcher banner, the in-app welcome background, and any Play Store / feature-graphic style assets — using the canonical EH! IPTV line art. The work is **purely visual**: a Python script regenerates each density variant from the source artwork and overwrites the files in `app/src/main/res/`. No XML, no Kotlin, no manifest changes. A single `assembleDebug` refreshes `app/build/intermediates/packaged_res/...` and the new APK ships the new art.

## When to apply

- After a brand change (new logo, new colors, new mascot) and you need every visible image surface updated in one pass
- After skill #10 (`customise-accent-colors.md`) changes the brand color, because the banners use the same brand orange
- The `drawable/app_banner.png` (and its density variants) or `drawable/welcome_bg.png` still show the old StreamVault branding

## The source of truth

There is **one** canonical artwork in the project, used as input for every other big art surface:

```
app/src/main/res/drawable-xxxhdpi/ic_launcher_vault_art.png
```

(432×432, transparent background, orange line art of a TV with two people watching + the "EH! IPTV" text. Also exists in `drawable-mdpi` through `drawable-xxxhdpi` for the adaptive icon foreground.)

When the brand changes, you only need to update this one file. Everything else (launcher icon, adaptive icon, TV banner, welcome background) flows from it.

## What's in the res/ tree

| File | Purpose | Density variants? | Source? |
|---|---|---|---|
| `drawable/ic_launcher_vault_art.png` (in `drawable-*/`) | Foreground art for the adaptive icon, referenced by `mipmap-anydpi-v26/ic_launcher_vault.xml` → `drawable/ic_launcher_foreground.xml` → `@drawable/ic_launcher_vault_art` | Yes (5 densities: mdpi 108 → xxxhdpi 432) | Canonical — update here first |
| `mipmap-*/ic_launcher_vault.png` (5 densities) | Legacy launcher icon for pre-API 26 devices, also used by some launchers as the rounded icon | Yes (5 densities) | Update by resizing the canonical art (see script) |
| `drawable/app_banner.png` (in `drawable-*/`) | Android TV launcher banner (the "card" you see in the TV's app row). 16:9 aspect ratio. | Yes (5 densities) | Regenerate from canonical art |
| `drawable/welcome_bg.png` | Welcome screen background (the in-app background, used by `WelcomeScreen.kt` as a fallback or in previews). 3:2 (1536×1024) aspect ratio. | No (single file) | Regenerate with the image_synthesize tool |
| `mipmap-anydpi-v26/ic_launcher_vault.xml` | Adaptive icon descriptor (foreground + background). Foreground is `@drawable/ic_launcher_vault_art`, background is `@android:color/black`. | No (descriptor) | Do not change unless the brand has a different dark color than `#000000` |

## How to update

### 1. Update the canonical art (if the brand changed)

Replace `app/src/main/res/drawable-xxxhdpi/ic_launcher_vault_art.png` (and the smaller density variants) with the new logo. The 5 density files should be the same design at different resolutions — 108, 162, 216, 324, 432 px square. For a one-off brand swap, the xxxhdpi master is enough; the smaller densities can be generated by resizing.

### 2. Regenerate the mipmap launcher icons

Use the script below. It reads the canonical xxxhdpi art and produces matching launcher icons at the standard Android TV mipmap densities. The result is a clean orange line-art icon on a black square — no cropping, no extra decoration.

### 3. Regenerate the app_banner (Android TV launcher card)

Use the same script. The banner keeps the 16:9 aspect ratio of the existing files (which are intentionally non-standard densities — see "Anti-patterns" below for why we don't touch the dimensions).

### 4. Regenerate the welcome_bg

The welcome background is a single file, not density-aware. Use the `image_synthesize` tool with the canonical art as a reference and a prompt like:

> Cinematic 16:9 background for an IPTV app welcome screen. Dark navy blue background (#07111B) with subtle radial light effects. Centered orange line-art logo of a TV with two people watching, with the text "EH! IPTV" below it in clean modern typography (orange #FF6A1A). Faint film-strip and play-button motifs on the edges as soft decorative elements. Subtle horizontal light streak in the middle. Premium, dark, cinematic atmosphere.

The result will be ~2528×1696. Resize it to **1536×1024** (matching the original StreamVault welcome_bg dimensions) to keep the APK small. The aspect ratio (~3:2) doesn't quite match TV 16:9, but the original had the same ratio and the user accepted it.

### 5. Rebuild

```bash
./gradlew :app:assembleDebug --no-daemon
```

The `app/build/intermediates/packaged_res/.../app_banner.png` and `.../welcome_bg.png` get regenerated from source automatically. No manifest changes, no Kotlin changes.

## The Python script

Save as `make_banners.py` somewhere on your PATH (e.g. `/tmp`), run once per brand change:

```python
"""Regenerate all app_banner.png and mipmap-*/ic_launcher_vault.png from the canonical
ic_launcher_vault_art.png. The art's transparent background blends seamlessly with the
dark Canvas color (#07111B) we set as the canvas — no black box artifact.

Composition:
  - background: #07111B (AppColors.Canvas) so it matches the app's dark surfaces
  - foreground: the canonical art, scaled to fit (contain) — no edge crop
  - aspect ratio: preserved per existing file (16:9 for banners, 1:1 for mipmaps)
"""
import os
from PIL import Image

ART_PATH = r"app/src/main/res/drawable-xxxhdpi/ic_launcher_vault_art.png"
RES_ROOT = r"app/src/main/res"
BG_COLOR_RGBA = (7, 17, 27, 255)   # #07111B
BG_COLOR_RGB = (7, 17, 27)
PADDING = 0.08  # 8% padding on each side of the contained art

art = Image.open(ART_PATH).convert("RGBA")

for dirpath, _, files in os.walk(RES_ROOT):
    for f in files:
        if f != "app_banner.png" and f != "ic_launcher_vault.png":
            continue
        path = os.path.join(dirpath, f)
        existing = Image.open(path)
        w, h = existing.size
        out_mode = "RGBA" if existing.mode == "RGBA" else "RGB"

        if out_mode == "RGBA":
            canvas = Image.new("RGBA", (w, h), BG_COLOR_RGBA)
        else:
            canvas = Image.new("RGB", (w, h), BG_COLOR_RGB)

        # Contain: scale art to fit entirely inside the canvas, no crop
        available_w = int(w * (1 - 2 * PADDING))
        available_h = int(h * (1 - 2 * PADDING))
        scale = min(available_w / art.size[0], available_h / art.size[1])
        new_w = int(art.size[0] * scale)
        new_h = int(art.size[1] * scale)
        art_resized = art.resize((new_w, new_h), Image.LANCZOS)

        paste_x = (w - new_w) // 2
        paste_y = (h - new_h) // 2

        if out_mode == "RGBA":
            canvas.alpha_composite(art_resized, (paste_x, paste_y))
        else:
            rgba = canvas.convert("RGBA")
            rgba.alpha_composite(art_resized, (paste_x, paste_y))
            canvas = rgba.convert("RGB")

        canvas.save(path, "PNG", optimize=True)
        print(f"wrote {path}  {w}x{h}  art-fit {new_w}x{new_h}")
```

Run it after updating the canonical art. The script walks the whole res tree and only touches `app_banner.png` and `ic_launcher_vault.png` — it won't touch `ic_launcher_vault_art.png` itself.

## What changes visually

After running the script + rebuild + install:

- The Android TV launcher card for the app shows the new banner (TV + people + "EH! IPTV" on dark navy, no edge crop)
- The app's launcher icon (the rounded square in the app row) shows the new icon
- The adaptive icon (the splash + the long-press effect) shows the new icon on the adaptive background
- On Android 8+ devices that use the adaptive icon, the visual is identical to the launcher icon. On older devices, the legacy `mipmap-*/ic_launcher_vault.png` is used and is now updated too

## What does NOT change

- `mipmap-anydpi-v26/ic_launcher_vault.xml` — the adaptive icon descriptor. Foreground stays `@drawable/ic_launcher_foreground` (which points to the art). Background stays `@android:color/black` (pure black, gives the splash its signature look).
- `drawable/ic_launcher_foreground.xml` — its content (`<bitmap android:src="@drawable/ic_launcher_vault_art" android:gravity="fill"/>`) is correct as-is, no edit needed.
- `drawable/ic_launcher_vault_art.png` (in `drawable-*/`) — these are the input, not the output. The script never writes to them.
- Any drawable other than `app_banner.png` and `ic_launcher_vault.png` — the script is scoped tightly to those two filenames.

## Anti-patterns (do not)

- Do **not** use `cover` scaling (scale to fully cover, then center-crop). The icon's edges — the TV's left/right frame and the "EH! IPTV" text — are at the borders. Cropping cuts them off and the banner ends up showing "HI IPTV" instead of "EH! IPTV". Always use `contain` (fit inside, never crop).
- Do **not** use the attachment path the user gave you instead of the source `drawable-xxxhdpi/ic_launcher_vault_art.png`. The source file is the canonical 432×432 art; the attachment is a smaller 176×176 thumbnail that loses quality when scaled up.
- Do **not** change the dimensions of the existing `app_banner.png` files. The dimensions are unusual (160×90, 240×135, 320×180, 480×270, 640×360) but the **proportions** are what matter — 16:9. Android TV scales the banner to fit the launcher row, so the actual pixel dimensions are noise.
- Do **not** edit `mipmap-anydpi-v26/ic_launcher_vault.xml` to point at a new foreground bitmap. The `@drawable/ic_launcher_foreground` indirection is what lets the file be either XML (vector) or PNG (bitmap) without breaking the adaptive icon — keep it.
- Do **not** create new `drawable-*/welcome_bg.png` variants. `welcome_bg.png` lives in `drawable/` (no density qualifier) and is used at its native 1536×1024. If you need it on a smaller screen, the system downscales.

## Verification

1. **Build and install** (the build is incremental, ~3-5 min):

   ```bash
   ./gradlew :app:assembleDebug --no-daemon
   adb -s <device> install -r app/build/outputs/apk/debug/app-debug.apk
   ```

2. **Open the app on the TV** and check the launcher card. The banner should show the orange line-art TV + people + "EH! IPTV" text fully visible, no edge crop, on the dark navy background.

3. **Long-press the app icon** to see the adaptive icon effect (the icon scales up with a circular mask). The text and art should still be readable.

4. **Compare** with one of the `drawable-*/app_banner.png` files you just wrote — the banner on screen should look like the file.

5. **For the welcome background** specifically: open the Welcome screen and confirm the background looks like the welcome_bg you generated. Note: the actual Welcome screen uses a `Brush.verticalGradient` (in `WelcomeScreen.kt:238-246`) — the `welcome_bg.png` is only used as a fallback or in Compose previews. If the gradient still looks like the old brand, the actual issue is in `AppColors.HeroTop` / `AppColors.HeroBottom`, not in `welcome_bg.png`.
